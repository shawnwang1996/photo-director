# 拍照导演 · PWA v0.9

一个人举手机、一个人站着——先告诉「站哪、机位多高」，再告诉「人怎么摆」，按提示连拍 3 张，挑一张就能发。

纯前端单页，**零后端、零费用、零安装**：扫码打开就能用，加到主屏幕就是一个 App。

**线上地址**：<https://shawnwang1996.github.io/photo-director/>（GitHub Pages，自带 https，手机上打开就能开相机）

---

## 1. 现在能跑什么

| 能力 | 说明 |
| --- | --- |
| 实时取景分析 | 手机后置摄像头每隔 280ms 分析一次画面：视觉重心、地平线高度、顺光/逆光、场景类型，结果用 EMA 平滑，避免抖动 |
| 画面叠加 | 三分网格、黄色虚线地平线、青色人框、白色骨架、脚下两条亮线；全部是百分比定位，跟着镜头比例自适应 |
| 双身份口令 | 「教摄影 · 怎么构图」（站哪/机位/曝光/表情）与「教模特 · 怎么摆」（站哪/姿势/手/脸），四张卡 + 5 条步骤 + 一句「只改一个错」 |
| 三场景 | 草地逆光 / 城市街拍 / 林间小路，自动识别也支持手动切换；每个场景 3 个姿势 |
| 连拍 | 3 秒倒计时 → 连拍 3 张 → 结果页挑图，可系统分享（不支持时降级下载） |
| 无相机也能演示 | 首页「看示例」三个按钮，用内置样张跑完整流程（也用于自动化测试） |

主文件：`index.html`（单文件 UI + 状态机）、`analyze.js`（像素分析）、`poses.js`（6 个姿势数据）、`sw.js`（离线缓存 v2）、`manifest.webmanifest`（可加到主屏幕）。

## 2. 本地跑起来（30 秒）

```bash
cd fde-research/pose-demo
python3 -m http.server 8099 --bind 127.0.0.1
# 打开 http://127.0.0.1:8099/pwa/
```

注意两点：

1. **http 下打不开摄像头**（Safari/Chrome 都要求 https 或 localhost）。在电脑上 localhost 算安全上下文，可以用相机；用手机连局域网 IP 访问时，只能点「看示例 / 选相册照片」。
2. 想手机上真机试相机，直接跳到第 3 步部署——GitHub Pages 自带 https。

## 3. 部署到 GitHub Pages（全免费）

### 方式 A：命令行（推荐）

```bash
gh auth login                      # 浏览器授权一次
cd fde-research/pose-demo/pwa      # 这个目录就是站点根目录
git init -b main
git add . && git commit -m "photo director pwa v0.9"
gh repo create photo-director --public --source=. --push
gh api -X POST repos/:owner/photo-director/pages \
  -f 'source[branch]=main' -f 'source[path]=/'
```

等 30 秒，地址是 `https://<你的用户名>.github.io/photo-director/`。

### 方式 B：网页

新建仓库 → 上传 `pwa/` 里的全部文件到仓库根目录 → Settings → Pages → Source 选 `main / (root)` → Save。

### 换域名 / 加速

GitHub Pages 在国内偶尔慢，可换 **Cloudflare Pages**（免费，连 GitHub 仓库自动构建，带全球 CDN），或买个域名（¥60–80/年）绑上去。不买也能用，`*.github.io` 够用。

## 4. 分析是怎么做的（没有任何模型）

端侧纯 JS 像素计算，单帧 4–17ms：

1. 灰度 → **Sobel 边缘图** → 归一化，再用 `boxBlurMean` 得到稠密评分，作为「显著性」的代理（Python 版用 FFT 谱残差，效果接近但 JS 版更快）。
2. `colorDev` = 每个像素与全图平均色的欧氏距离；最终 `sal = 0.62 * edge + 0.38 * colorDev`。
3. **地平线**：逐行求梯度，取 0.35H–0.78H 之间梯度最大的一行。
4. **天空比例**：顶部 32% 行里 `V > 0.55 且 S < 0.38` 的占比；再用「上部亮 vs 下部亮」判断 **逆光**。
5. **场景**：天空占比 > 30% 判草地，否则判街拍。
6. **人框**：在高度候选 [0.42, 0.5, 0.6]、横坐标步长 4%、脚底 90–94% 上滑窗打分（框内显著性 − 框外），靠近 1/3、2/3 三分线额外加分；宽 = 高 × 0.44 × 画幅比。

### 和 Python 版（`pose-demo/analyze.py`）的已知差异

同一张 160×120 缩略图交叉验证：

| 指标 | JS | Python | 结论 |
| --- | --- | --- | --- |
| 地平线（草地样张） | 0.425 | 0.448 | 差 2 个百分点，一致 |
| 天空占比 / 顺逆光 | 1.0 / 逆光 | 一致 | 一致 |
| 人框横向（草地） | 0.58 | 0.58 | 一致 |
| 人框横向（街拍） | 0.38 | 0.06 | 差 32 个百分点，**显著性代理不同导致** |
| 人框高度（小路） | 0.30–0.60 | 0.48–0.42 | 差 18 个百分点 |

**结论**：地平线、天空、顺逆光可信；人框位置是「建议值」，不是测量值——同一场景换台手机、换个构图就可能偏 10–30 个百分点。所以叠加层只是「往这放」的参考，别当成硬约束。真要准，v2 换 Vision 人体框（原生）或 MediaPipe Pose（Web）。

## 5. 已知边界

- 高频纹理场景（草地、树林、密集招牌）容易把「视觉重心」判到天上或两侧，人框偏。
- 逆光判断只看上下亮度差，不识别真实光源，阴天会判成顺光。
- 只支持单人；情侣双人合影要先按一个人给框，再口头补一句「两个人各站一条线」。
- 没有美颜、没有滤镜、不修图——只解决「按快门之前那十秒」。
- `?demo=field|street|path` 是测试用的示例入口，正式推广别外传这个参数（不影响功能）。

## 6. 下一步（关卡 2 要出的数字）

1. 找 2 对情侣/闺蜜，各拍 10 张，盲评「这张能发吗」，两人独立打分取均值 → **首张可用率**，目标 ≥ 60%。
2. 记录「举起手机 → 按下快门」的秒数 → **决策时长**，目标 < 20 秒。
3. 拍完问一句「刚才第一句让你干嘛」→ **口令可复述**，目标 4/5 人能答对。

三个数拿到，再把口令从 12 字压到 10 字以内、把偏得最多的那类场景（大概率是草地人框）单独调规则。
